# 踩坑清单（Kindle + Reader3 + 书源）

按「以后跟着项目走不走弯路」整理，每条都是实测踩出来的。

> 时间 **2026-11-07**。覆盖：番茄书架分组、Reader3 部署、书源换源、Kindle 插件。

## 1. 书源不随书单同步（最核心的坑）

**现象**：手机「阅读」App 里加的书，同步到 Reader3 后打不开，报「未找到书源 / 目录为空」；但网页版能看。

**根因**：手机 App 和 Reader3 是**两套独立书源库**。书架同步只同步书单 + 每本书绑定的 `origin`（书源 URL），**不同步书源抓取规则**。手机的小众源（siluke5/eyagu/zhaishuyuan 等）在 Reader3 服务端书源库（352 个活源）里不存在。

**教训**：
- 想多端通用，书要在**网页版（服务端）搜索加书**，绑定服务端书源库里的源。
- 手机 App 加的书如果用了小众源，同步过来就是死源。
- 数据验证：书架 `origin` 有 107 种，其中 104 种不在服务端书源库。

## 2. getChapterList 参数是 bookUrl 不是 origin

**坑**：排查时用 `origin`（书源 URL）当 `getChapterList` 的 `url` 参数，结果是错的。

**正确**：`url` 参数是 `bookUrl`（具体书页，如 `https://www.deqitxt.com/287/`），不是 `origin`（书源 URL）。

**教训**：先看接口返回的书对象字段语义，`bookUrl` 和 `origin` 是两个不同的东西。

## 3. setBookSource 用死源 bookUrl 会「书籍信息错误」

**坑**：换源接口 `POST /setBookSource`，如果传的 `bookUrl` 是**死源地址**，服务端按它定位书失败 → 返回 `书籍信息错误`（因为服务端书架里该书已经是活源 bookUrl，按死源定位不到）。

**正确做法**：
- 先 `getBookshelf` 拿服务端活源 bookUrl，再操作。
- 或换源参数里 `bookUrl` 用当前（活源）bookUrl，`newUrl`/`bookSourceUrl` 用新候选源。

**教训**：换源前必须知道书在服务端书架里的**当前 bookUrl**，不能拿本地旧值。

## 4. TocEmptyException = 下载正文用死源

**坑**：目录换源成功了（getChapterList 返回正常章节），但下载正文还是报 `io.legado.app.exception.TocEmptyException:目录为空`。

**根因**：下载正文链路 `chapter.bookUrl` 从本地 books 表读（死源），换源改的是目录流程里的独立对象，没写回。且 `_isSourceDeadError` 没把 `TocEmptyException/目录为空` 当死源错误。

**教训**：
- 换源要在**目录和正文两个入口**都做（getChapterList + getBookContent）。
- 换源成功后要把活源写回 `bookinfo` 引用（引用传递，非拷贝）。
- 死源错误匹配要覆盖异常类型字符串（`TocEmptyException`）+ 中文提示（`目录为空`）。

## 5. getAvailableBookSource 对死源书返回「书籍信息错误」

**坑**：`POST /getAvailableBookSource` 对死源 bookUrl 返回「书籍信息错误」——该接口需先访问 bookUrl 解析书名，死源页打不开。

**正确做法**：用 `searchBookMultiSSE?key=书名`（按书名多源搜索，SSE 流），拿到候选源列表，作者精确匹配。

**教训**：死源场景下，所有「按 url 解析」的接口都失效，只能用「按书名搜索」。

## 6. fbink 缺失导致 KOReader 启动卡屏

**坑**：重启 KOReader 后卡住，进程只占 11MB 内存、0 CPU，日志停在 zstd 加载。根因是 `/var/tmp/fbink: not found`。

**修复**：`cp /mnt/us/koreader/fbink /var/tmp/fbink` 后重新重启。

**教训**：KOReader 重启异常时先查 crash.log 尾部，看是不是 `/var/tmp` 下的运行时依赖丢了。

## 7. KOReader 重启会重置 preventScreenSaver

**坑**：设了 `settings.reader.lua` 的 `auto_standby_timeout_seconds=-1` / `auto_suspend_timeout_seconds=-1` 以为不会休眠，但重启后 `preventScreenSaver` 被重置为 0，Kindle 还是休眠 → WiFi 断 → SSH 连不上。

**正确做法**：后台 keepalive 脚本持续设 `preventScreenSaver 1`（见 [13-防休眠](13-防休眠.md)）。

## 8. 书源健康同步会自动删不健康源

**坑**：服务端书源库从 451 个缩到 352 个（删了 97 个），是「书源健康同步」机制自动删的。

**证据**：`/logs/sync.log` 记录 `subscription=451 reader=451 healthy=380 failed=41 skipped=30 deleted=0`；`sync-state.json` 逐源 health check。

**教训**：
- 服务端书源库是「订阅合集」，会被自动清理。
- 被删源有快照：`/logs/booksource-before-delete-*.json`。
- 用户书架绑定的源若被删，打开书就会「未配置书源」。

## 9. luajit -bl 不可用（KOReader 剥离 jit 模块）

**坑**：想用 `luajit -bl` 编译校验语法，报 `unknown luaJIT command or jit.* modules not installed`。

**正确**：用 `luajit -e "loadfile('文件')"` 或写个 `check.lua` 遍历 `arg` 逐个 `loadfile`。

```lua
-- check.lua
for i=1,#arg do
  local fn,err = loadfile(arg[i])
  if fn then print(arg[i], "SYNTAX OK")
  else print(arg[i], "FAIL:", err) end
end
```

## 10. bookCacheId = md5("书名 (作者)")

**坑**：本地数据库主键 `bookCacheId = md5("name (author)")`，作者名 `author` 为 nil 会生成**错误 id**（不是同一本书）。

**教训**：拿完整书记录（含 author）再算 id；`getBookInfoCache(bookCacheId)` / `getBookinfo(bookShelfId, bookCacheId)` 返回含 name/author/bookUrl/origin 完整记录，不要从章节表里拼 author。

## 11. 番茄书架分组的 group_id 是 JSON number > 2^53

**坑**：番茄官方接口返回 `group_id` 是 JSON number，超过 2^53，LuaJSON 解成 double 会丢低位。

**实际影响**：同一分组的 group_id 整数一致，解成同一 double，等值比较（`book.group_id == group_id`）**安全**，不会碰撞（实测 6 个分组 → 6 个不同 double）。book_id 是 JSON string，精确。

**教训**：Lua 里 JSON number 精度丢失要按「同值比较」判断，不要序列化后做字符串拼接匹配。

## 12. 番茄插件分组：服务端返回了 group_id/group_name 但插件没解析

**坑**：番茄书架接口明明返回 `group_id` + `group_name`，但插件书架没有分组——是插件 `fetch_shelf_detail` 从 `shelf_meta` 只拷了 `add_shelf_time/last_operate_time/asterisked/add_type`，**漏了 group 字段**，不是服务端没返回。

**教训**：排查「功能缺失」先看插件解析代码是否丢弃了服务端字段，别急着怀疑服务端。

## 13. Kindle SSH 空密码 + 引号转义

**坑**：
- root 空密码，连接必须带 `-o PreferredAuthentications=password -o PubkeyAuthentication=no`，否则 `Permission denied (publickey,password)`。
- 本机 Windows 的 `ssh.exe` 连空密码会交互卡死，改用 paramiko 脚本（`kssh.py`）稳定。
- `luajit -e "loadfile('...')"` 通过 SSH 多层引号转义会 `unfinished string`，写成脚本文件传回执行最稳。

**教训**：复杂命令写成本地脚本 → scp 传回设备 → 设备上执行，别在 SSH 命令行里硬套引号。

## 14. 书源里混着词典源和 txt 存储站

**坑**：书源库里混着垃圾源：`dict.cn`（词典，返回搜索跳转页非书页）、`cunshu.la`（txt 存储站，返回整页 HTML）、`5sing.kugou.com`（音乐站）。换源匹配到这些源会「书籍信息错误」或「ScriptException」。

**教训**：批量换源要维护**问题源黑名单**（is_bad），换源前排除。已确认黑名单：`bookshelf.html5.qq.com`(QQ阅读 intro-info 接口异常)、`cread.com`(时间字段 bug)、`dict.cn`、`8biquge.com`、`cunshu.la`、`5sing.kugou.com`、url 含 `search.php` 的搜索跳转页。

## 15. loc_book 是手机本地书，无法换源

**坑**：书架里 `origin=loc_book` 的书是手机本地 txt/epub，`bookUrl` 是 `content://com.android.externalstorage.documents/...`。服务端 getChapterList 返回「本地书籍源文件不存在」，无法换源。

**教训**：loc_book 的书要么在手机 App 本地看，要么重新用网络书源在服务端加书。
